# X-STATION V2 Wacom 手写笔适配方法

日期：2026-10-28
前提：手指触摸已在 v0.1.41 起用 VoodooI2C 2.8 组验证可用（见 `xstation-v2-touch-driver-research-20261025.md`）。
本文只管**笔**：悬停、笔尖、笔侧键、橡皮擦、压感、倾斜。

## 1. 硬件事实

- 传感器：`\_SB.PC00.I2C1.TSC1`，`_HID WCOM4815`，`_CID PNP0C50`，I²C 地址 0x0A，HID `056A:48EE`。
- Linux 把同一个 I2C HID 设备拆成 `Wacom HID 48EE Pen` 和 `Wacom HID 48EE Finger` 两个输入节点：
  笔和手指是**同一个 HID 设备里的不同 report/collection**，不是两个硬件。
- macOS 侧链路：`VoodooI2C`（控制器）→ `VoodooI2CHID`（PNP0C50）→ 按 HID 描述符里的 Digitizer 集合分发。
  - 手指：Digitizer / Touch Screen（Usage 0x0D/0x04）
  - 笔：Digitizer / Pen（Usage 0x0D/0x02）

## 2. 不推荐的路线

- **Wacom 官方 macOS 驱动**：只认 USB/蓝牙数位板的已知型号，不认 I2C 内嵌屏（AES/EMR in-cell）。伪装 VID/PID 也接不上 I2C 传输层。不做。
- **额外装 ELAN/Atmel/Synaptics 等 VoodooI2C 插件**：这块屏走标准 HID-over-I2C，不需要。
- **为了笔改 DSDT/GPIO**：手指已正常，说明中断和 I²C 都没问题。笔若有问题，出在 HID 分发或用户态，不在 ACPI。

## 3. 步骤（每步一个变量，失败就停下）

### W0 硬件基线（Linux Live，零风险）

先确认笔本身是好的，比如电池有电、笔尖没坏：

```bash
sudo apt-get install -y evtest
sudo evtest   # 选 "Wacom HID 48EE Pen"
```

需要看到这些事件：`BTN_TOOL_PEN`（悬停/接近）、`BTN_TOUCH`（笔尖）、`ABS_X/ABS_Y`、`ABS_PRESSURE`（压感，记下最大值），有的话还有 `BTN_STYLUS`/`BTN_STYLUS2`（侧键）、`BTN_TOOL_RUBBER`（橡皮擦）、`ABS_TILT_X/Y`（倾斜）。
同时导出 HID 描述符作为对照：`sudo cat /sys/kernel/debug/hid/*056A:48EE*/rdesc > wacom-48ee-rdesc.txt`。
**Linux 下笔就不工作的话，先换电池或换笔，不往下做。**

### W1 macOS 现状（只读，不改 EFI）

```bash
ioreg -lw0 -r -c VoodooI2CHIDDevice | grep -E 'ReportDescriptor|DeviceUsagePairs|PrimaryUsage'
ioreg -lw0 -r -c VoodooI2CMultitouchHIDEventDriver
```

- `DeviceUsagePairs` 里要有 `0x0D/0x02`（Pen）。
- 解出 `ReportDescriptor`，和 Linux 的 rdesc 对比 Pen 集合：Tip Switch、In Range、Barrel、Invert/Eraser、Tip Pressure 的位宽、Logical Max、X/Y Tilt。

**2026-10-28 实测（v0.1.50）**：`VoodooI2CHIDDevice` 的 `DeviceUsagePairs` 含 `0x0D/0x04`（Touch Screen）、
`0x0D/0x02`（**Pen**）、`0x0D/0x0E`、`0x0D/0x20`（Stylus）、Wacom 厂商页 `0xFF11`/`0xFF14`、`0x01/0x01`/`0x01/0x02`；
驱动为 `VoodooI2CTouchscreenHIDEventDriver`。→ Pen 集合已被枚举，W1 通过，下一步直接做 W2 实测。

### W2 macOS 行为实测（不改 EFI）

逐项打勾：

| 项目 | 期望 |
|---|---|
| 悬停 | 笔离屏 5–10 mm 时光标跟随，不点击 |
| 笔尖 | 等同左键按下/拖动 |
| 侧键 | 等同右键（或可映射） |
| 橡皮擦 | 笔翻转后有区分（若硬件支持） |
| 压感 | 应用读到连续变化的 pressure（0–1） |
| 手掌 | 笔在范围内时，手掌接触不乱点 |

压感不能靠肉眼判断，用一个小测试程序读 `NSEvent.pressure` / `tabletPoint` 事件来验证（Swift，几十行，放 `scripts/pen/`）。

VoodooI2C 2.x 的事件驱动内置了基础手写笔处理：笔会作为绝对坐标指针，笔尖是左键，侧键是右键，压感作为 digitizer 事件下发。所以**预期 W2 时就能用一大半**，压感和倾斜能不能被 macOS 应用读到需要实测。

### W3 按 W2 结果分支

| 现象 | 处理 |
|---|---|
| 全部正常 | 结束，在 test-matrix E3 记录"通过" |
| 能移动和点击，**没压感** | 优先做**用户态补全**：一个 LaunchAgent 用 IOHIDManager 读 48EE 的 Pen report，生成带压感的 tablet 事件（CGEvent tablet pointer/proximity）。不碰内核，可随时停用 |
| 坐标偏移/缩放不对（笔和手指不一致） | 核对 Pen 集合的 Logical/Physical Max 与屏幕旋转；VoodooI2C 按描述符缩放，偏差一般出在描述符解析，记录后找上游 issue 或在用户态矫正 |
| 笔完全没反应、Linux 正常 | 检查 W1 的 `DeviceUsagePairs` 有没有 Pen；没有的话是 VoodooI2CHID 没枚举出 Pen 集合，先换 VoodooI2C 最新 release 对照（单变量，只换这一组 kext） |
| 手指和笔互相抢 | 记录场景；必要时用户态在笔 In Range 时忽略手指（palm rejection） |

### W4 收尾

- 结果写进 `docs/test-matrix.md` 的 E3、`docs/current-handoff.md`。
- 用户态补全如果做了，源码和 LaunchAgent plist 放 `scripts/pen/`，装/卸都要有一条命令。

## 4. 约束

- 不和电源键、睡眠、音频的改动放在同一轮。
- W0–W2 都不改 EFI；只有 W3 的"换 VoodooI2C 版本"需要刷 U 盘，按惯例先备份并征得同意。
- 不写内置 ESP。

## 5. 结果（2026-10-29）

- W2 原始数据：笔数据以标准 Pen report 20 到达 macOS（`work/reports/pen-20261029/`），压感最高 3100/4095。
- 根因：VoodooI2C 2.8 的 Touchscreen 事件驱动不解析 Pen 集合（上游 VoodooI2CHID #72 修复）。
- 修复：v0.1.51 = VoodooI2C 2.9.1 全套 + 本机两项匹配补丁（I2C `0xa0e88086&0xFFFCFFFF`、GPIO IceLakeLP `INT34C5`）。
  注意：不能只换 VoodooI2CHID（2.9.1 的 transducer 类布局变了）；官方 2.9.1 不带这两项匹配会导致触摸全失效。
- 验收：悬停、笔尖、拖动、侧键右键、橡皮擦正常；手指触摸正常。
- 待办：应用内压感（NSEvent.pressure）验证；rid 255 空报告约 180/s（轮询），可试 GPIO 改配 TigerLakeLP。
